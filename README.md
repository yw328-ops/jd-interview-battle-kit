# JD 面试作战包（jd-interview-battle-kit）

> 先判断值不值得投，再决定怎么赢。

**当前版本：1.3.3**

一个把「岗位评估 + 面试准备」做成固定流程的 AI Skill：收到 JD 后**先判断岗位值不值得投入**，默认只给一页作战摘要；只有用户明确要继续，才进入岗位重点、个人经历与面试练习材料的整理。

## 它解决什么问题

- **避免做无用功**：用户容易对每份 JD 都投入同样多的准备时间——本 Skill 先判断投入方式（近期主攻 / 战略探索 / 低成本验证 / 暂缓投入），再决定投入多少。
- **避免准备堆量**：默认只给一页结论；材料按优先级分为「必须先准备 / 有时间再准备 / 暂时不用准备」，不列几十道题吓人。
- **避免 AI 编造经历**：所有经历只用四种分类（直接做过 / 可以迁移 / 还没说 / 确实没有）硬性约束，不编造任何数字、职责、结果。

## 核心特点

- 判断档位固定：近期主攻 / 战略探索 / 低成本验证 / 暂缓投入，不出现"中至高"这类模糊档位
- 三阶段渐进：一页作战摘要 → 岗位作战地图 → 可直接练习的面试材料，每阶段需用户明确要求才进入
- 不编用户经历：做过就是做过；没说不等于没有；确实没有也不能硬编
- 保留用户自己的说话方式，不统一改写成 AI 口吻
- 上下文复用：用户说过一次的经历，多个岗位反复使用，不从头问起
- 收尾闭环：无论沟通几轮，最后收敛成一张最终一页纸总结

## 快速开始

1. 安装：见 `INSTALL.md`（Hermes 技能库 / ChatGPT 自定义指令 / 通用复制均可）
2. 把一份 JD（文字、截图、链接内容）发给 AI
3. AI 先给**一页作战摘要**：结论 + 现在能不能做 + 对下一步价值 + 最大风险 + 现在先做什么
4. 说「继续准备」，进入第二阶段：岗位作战地图 + 个人经历整理
5. 说「开始练习」，进入第三阶段：项目故事 + 回答骨架 + 高概率问题
6. 说「总结一下」，输出最终一页纸总结收尾

## 验收标准（跑完自查）

- 第一阶段默认一页（600-900 字），最多一张核心表格
- 不出现伪精确分数（匹配度 82%）和内部代号（J1 / P / Q）
- 所有经历判断只用四种分类，不编造任何数字、职责、结果
- 用户没提供未来方向时，岗位价值诚实写「目前还看不出来」
- 档位只用固定四档，不出现"中至高""偏高"等变体
