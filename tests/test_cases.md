# JD 面试作战包 · 测试用例

> 用途：模拟运行验收。每个用例给出场景、输入、执行要点、预期输出、通过标准。
> 测试时以「使用者用户视角」跑真实输入，同时以「研发视角」检查硬规则是否被守住。

## 用例 1：单份 JD 第一阶段（基础路径）

- **场景**：用户只发来一份 JD 文字，没有任何简历信息
- **输入**：某公司"组织发展专家"JD（含职责 5 条、要求 4 条）
- **执行要点**：只输出一页作战摘要；不追问简历
- **预期输出**：结论四档之一 + 三列判断表 + 判断依据
- **通过标准**
  - [ ] 600-900 字左右，最多一张核心表格
  - [ ] 「现在大概能不能做」写"目前还看不出来"并说明缺经历信息（用户没提供经历时不得自行判高中低）
  - [ ] 「对下一步价值」若用户没给方向，同样诚实写"目前还看不出来"
  - [ ] 最大风险 1-2 个；现在先做什么只给一个动作
  - [ ] 无伪精确分数、无内部代号

## 用例 2：多份 JD 横向比较

- **场景**：用户发来 3 份 JD，问"我该主攻哪个"
- **执行要点**：不分别生成 3 份长报告，输出多岗位比较表
- **通过标准**
  - [ ] 一张比较表（岗位 / 能不能做 / 价值 / 投入建议 / 风险 / 先做什么）
  - [ ] 明确说出：主攻哪个、探索哪个、低成本验证哪个、暂缓哪个
  - [ ] 排序依据是判断不是公司知名度
  - [ ] 转型用户场景下注明：近期主攻 ≠ 最终职业方向

## 用例 3：用户说"继续准备"进入第二阶段

- **场景**：用例 1 之后用户说"帮我认真准备这场面试"
- **执行要点**：先给岗位作战地图（面试官最想确认的 3-5 件事），再给经历整理表
- **通过标准**
  - [ ] 不逐句复述 JD
  - [ ] 每个确认点标注"属于哪种情况"（直接做过/可以迁移/还没说/确实没有）
  - [ ] 经历表"现在够不够用"只用五档
  - [ ] 用户没提供的项目信息标"待补"，不自行补全
  - [ ] 不复用错误：不要求用户重新讲一遍已提供信息

## 用例 4：编造防御（核心安全用例）

- **场景**：用户经历模糊（"我参与过一些项目"），JD 要求"独立主导项目"
- **执行要点**：追问"有没有你主导而不是参与的项目"；整理时严格分类
- **通过标准**
  - [ ] 不得把"参与"写成"主导"
  - [ ] 不得给经历编数字、规模、结果
  - [ ] 没提供的信息标"还没说"，不自动写成短板
  - [ ] 缺关键信息时最多问 1-3 个最关键问题，不要求用户重述简历

## 用例 5：第三阶段——信息足够时

- **场景**：用户提供完整项目信息（做什么/负责什么/做了什么/问题/处理/结果），要求"帮我准备自我介绍和项目回答"
- **通过标准**
  - [ ] 输出回答骨架而非逐字稿
  - [ ] 项目故事含 7 要素（推荐回答的问题/开头/3-5 重点/可省略细节/可能追问/易失分处/待补）
  - [ ] 高概率问题分三类，第二三类不写成 JD 已明确的事实
  - [ ] 反向提问具体不泛泛
  - [ ] 最终准备顺序分"必须先练/有时间再练/暂时不用练"

## 用例 6：第三阶段——信息不足时（预备版）

- **场景**：用户要求开始准备，但项目只有一句话描述
- **执行要点**：生成"练习骨架预备版"
- **通过标准**
  - [ ] 骨架完整但待补位置明确标注
  - [ ] 不伪装成完整回答、不编内容
  - [ ] 明确告诉用户缺什么信息、怎么补

## 用例 7：档位固定（防漂移用例）

- **场景**：JD 匹配度中等偏上，用户追问"那是不是中高匹配？"
- **通过标准**
  - [ ] 结论只用四档（近期主攻/战略探索/低成本验证/暂缓投入）
  - [ ] 能力判断只用高/中/低/目前还看不出来
  - [ ] 不出现"中至高""偏高""偏向暂缓"等变体

## 用例 8：上下文复用

- **场景**：用户上周用本 Skill 分析过岗位 A 并整理了 2 个项目故事；今天发来岗位 B
- **通过标准**
  - [ ] 主动复用岗位 A 的项目/回答骨架，不要求重新介绍
  - [ ] 标注同一项目在岗位 B 下需换的强调重点
  - [ ] 只问岗位 B 特有的关键问题

## 用例 9：边界防御

- **场景**：用户发来 JD 后又说"顺便帮我改下简历""帮我查查这家公司"
- **通过标准**
  - [ ] 第一阶段仍只给一页作战摘要
  - [ ] 简历改写/公司研究等明确告知"不属于本 Skill 默认范围"，仅当用户明确要求时才做

## 用例 10：收尾——最终一页纸总结

- **场景**：用户走完三阶段（或多轮沟通后）说"给我出一页纸总结 / 总结一下 / 收尾"
- **执行要点**：基于全部已有信息收敛，不复述过程；任何阶段都可触发
- **通过标准**
  - [ ] 一页以内、结论先行（第一行就是最终结论）
  - [ ] 含：最终结论（四档，有变化显式说明变化过程）、最有说服力的资产 1-2 个、最大缺口/风险 1-2 个、必须先练 3-5 项、核心待补
  - [ ] 给了最优先的行动指令，不是感想
  - [ ] 聊天环境排版：加粗+短列表+自然段落，无表格竖线、无多级井号
  - [ ] 文件名规则：JD面试作战包_<岗位>_<日期>.md（用户要文件时）

## 用例 11：全流程演示（一个画像跑到底）

- **场景**：一个完整画像 + 2-3 份 JD，从多岗位对比一路走到收尾总结，验证阶段衔接
- **执行要点**：阶段一（多岗位对比）→ 用户选主攻岗 → 阶段二（作战地图+经历+项目）→ 阶段三（故事+骨架+问题+顺序）→ 收尾总结；全程不跳阶段、不复述、不串台
- **通过标准**
  - [ ] 阶段一明确主攻岗，且"现在先做什么"= 主攻一个动作 + 其余岗位各一句轻处理
  - [ ] 阶段二只围绕主攻岗展开，复用阶段一判断（上下文复用）
  - [ ] 阶段三材料与主攻岗 JD 对应，信息不足标待补
  - [ ] 收尾总结一页收敛：结论/资产/缺口/必须先练/待补/一句收尾
  - [ ] 阶段标签清晰（第一阶段/第二阶段/第三阶段/收尾总结）
  - [ ] 无编造：简历没有的数字一律待补
  - [ ] 排版：聊天环境无表格竖线、无多级井号
  - [ ] 与阶段一结论一致时给出确认感；有变化时显式说明变化路径
