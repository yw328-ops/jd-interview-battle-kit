# 第二阶段模板：岗位作战地图 + 个人经历整理

> 使用时机：用户明确表示继续准备（"继续准备 / 展开分析 / 帮我整理岗位重点 / 我要认真准备这场面试"）后才使用。
> 硬规则：复用用户已提供的信息，不得要求重新讲一遍；经历只用四种分类；不编造。

## 产出一：岗位作战地图

不要逐句复述 JD。围绕面试官最想确认的事整理。

```markdown
# 岗位作战地图

## 面试官最想确认的事情

### 1. 需要确认的重点

（写面试官最想确认的一件事，共三至五件）

**为什么重要：**
**你目前能拿来讲的经历：**
**属于哪种情况：**
直接做过 / 可以迁移 / 还没说 / 确实没有
**当前风险：**
**下一步：**
```

### 整理时覆盖的八个问题

1. 面试官最想确认的三至五件事；
2. 为什么这些事情对岗位重要；
3. 用户目前有哪些经历可以说明；
4. 哪些经历是直接做过；
5. 哪些经历可以迁移；
6. 哪些信息还没说；
7. 哪些能力用户已明确没有；
8. 最先应该补清楚什么。

## 产出二：个人经历整理表

```markdown
| 面试官想确认什么 | 你有哪些真实经历能说明 | 现在够不够用 | 还需要补什么 |
|---|---|---|---|
```

「现在够不够用」只使用五档（不要用等级代号）：

- 这段经历很有说服力；
- 有用，但需要讲得更清楚；
- 有一点关系，但目前不够；
- 你还没说过，需要确认；
- 你已经确认没有。

## 产出三：项目经历整理

默认优先整理最值得讲的三个项目；只有一个或两个合适项目就只整理一两个，不强行凑数。

```markdown
## 项目一：<项目名>

- 当时是什么情况：
- 项目要解决什么：
- 用户本人负责什么：
- 用户做了哪些关键动作：
- 遇到什么难题：
- 用户怎么判断和取舍：
- 最后结果怎么样：
- 是否有数字、反馈或材料可以说明：

> 用户没有提供的部分，明确标注「待补」，不得自行补全。
```
