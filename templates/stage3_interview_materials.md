# 第三阶段模板：面试练习材料

> 使用时机：用户明确要求进入面试准备，且现有信息能支撑真实回答（项目做什么 / 本人负责什么 / 具体做了什么 / 遇到什么问题 / 如何处理 / 最后结果）。
> 信息不够时：生成「练习骨架预备版」，保留待补位置，不得伪装成完整回答。

## 产出一：项目故事

```markdown
## 项目故事：<项目名>

- 推荐用于回答什么问题：
- 建议开头怎么说：
- 必须说到的三至五个重点：
- 哪些细节可以省略：
- 面试官可能继续追问什么：
- 哪些地方容易说虚、说长或说过头：
- 仍需补充的信息：
```

不要把所有故事强行套成同一个模板；回答要适合口头表达，不是报告朗读。

## 产出二：核心回答骨架

根据岗位和用户实际，优先生成：自我介绍 / 为什么选择这个岗位 / 为什么你适合 / 为什么想转型 / 如何说明明显短板 / 为什么离开上一份工作 / 最相关项目 / 一次困难或失败经历 / 一次推动他人或跨部门合作的经历。

```markdown
## 问题：<问题名称>

### 回答主线
### 必须说到
1.
2.
3.
### 可以使用的真实经历
### 容易失分的地方
### 可能被追问
### 仍需补充
```

默认生成回答骨架，**不生成逐字背诵的长篇标准稿**。

## 产出三：高概率问题（必须分三类）

```markdown
## 高概率问题

### 第一类：JD 明确会确认的问题
（JD 已明确提出的职责、要求或结果）

### 第二类：根据岗位职责大概率会问的问题
（JD 没直接写成问题，但由工作内容可合理推断——不得写成 JD 已明确的事实）

### 第三类：需要通过公司研究或面试才能确认的问题
例如：团队当前阶段 / 汇报对象真实期待 / 岗位新增还是替补 / 业务当前最关键的问题 / 资源和权限范围
```

## 产出四：反向提问清单

优先帮用户确认（要具体，避免"请问公司的企业文化是什么"这种泛问）：

- 这个岗位入职后三个月最需要解决什么；
- Leader 判断一个人做得好的标准是什么；
- 团队现在最大的困难是什么；
- 岗位拥有多大的决策权和资源；
- 岗位是新增还是替补；
- 这个岗位未来可能的发展路径；
- JD 中尚不清楚的重要信息。

## 产出五：最终准备顺序

```markdown
# 最终准备顺序
## 必须先练
## 有时间再练
## 暂时不用练
```

避免用户无差别准备所有内容。
